# Other languages

Do not project conventions from another language onto an unlisted one.

Identify the exact language and version, official style or API guidance, compiler or interpreter, package manager, formatter, linter, static analyzer, type system, error model, resource model, concurrency model, compatibility promise, and standard test tools. Consult current primary documentation when any of these may have changed.

Prefer repository configuration over generic advice. Derive naming, file organization, line length, declaration placement, and documentation rules from the language and project rather than inventing universal thresholds. Use ecosystem-standard safe APIs and validation tools.

If authoritative guidance is unavailable or conflicting, state the uncertainty and follow the nearest maintained project precedent. Never claim production compliance without running the relevant toolchain.
