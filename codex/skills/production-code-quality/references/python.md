# Python

Follow the supported Python version and the closest repository `pyproject.toml`, `ruff.toml`, `.flake8`, `setup.cfg`, `.editorconfig`, formatter, linter, type checker, package script, and test runner. Run the repository wrapper first. If the project declares Ruff, use `python -m ruff format --check path/to/file.py` and its configured lint command. If it declares Black, use `python -m black --check path/to/file.py`. Do not install or substitute a formatter merely to create a gate.

When neither repository policy nor a selected formatter resolves form, use the PEP 8 fallback: four-space indentation, no tab indentation, a 79-column code target, and a 72-column comment or docstring target. These are Python ecosystem defaults, not overrides for configured Black or Ruff output. Black and Ruff normally target 88 columns and may emit longer unbreakable lines. Apply the shared line-width review and hard gate, and all shared function, class, file, nesting, complexity, and parameter thresholds, from [code shape and naming](code-shape-and-naming.md) without restating them here.

Use `snake_case` for variables, functions, methods, modules, and ordinary package components, `CapWords` for classes and exception types, and `UPPER_SNAKE_CASE` for constants when no closer convention applies. A leading underscore marks non-public implementation detail only where Python semantics or project policy support it. Keep importable filenames lowercase, normally `snake_case.py`. Preserve special names such as `__init__.py`, framework discovery names, and the configured test pattern. These naming forms come from PEP 8 and packaging practice. Repository and public API precedent still wins.

Replace a dense expression with a named helper when the helper makes behavior easier to read, test, or change. Use explicit concatenation or joining when constructing a string from separate literals, and avoid adjacent literal concatenation where a missing comma could silently change collection contents. Split slicing and striding into named steps when their combination obscures indexes or direction. Do not rely on a `for` target after the loop, and do not mutate a collection while iterating over it. Use `any` or `all` when either expresses the required short-circuit predicate directly.

Express maintained boundary contracts with type annotations when the repository's static analysis can use them, and configure strictness according to the project. Avoid mutable default arguments, bare `except`, exception swallowing, implicit global state, import-time side effects, and ambiguous truth tests. Preserve exception causes. For a public library, define a stable package surface and a root exception only when callers need insulation from internal organization. Use `warnings` for a planned compatibility migration when callers need a transition period.

Use the repository's virtual environment or equivalent isolation mechanism for reproducible dependencies. Use dataclasses, enums, protocols, iterators, and asynchronous APIs when they simplify the actual model. Do not force object orientation onto procedural work. Test supported interpreters and packaging behavior where compatibility matters. Do not add docstrings unless the user or repository contract requires them, and keep required docstrings accurate.

Primary references: [Python documentation](https://docs.python.org/3/), [PEP 8](https://peps.python.org/pep-0008/), [Ruff formatter](https://docs.astral.sh/ruff/formatter/), [Black style](https://black.readthedocs.io/en/stable/the_black_code_style/current_style.html), and [Python typing](https://typing.python.org/).
