# Build CLI Tools

1. Establish the requested command behavior, users and automation consumers, supported operating systems and shells, runtime versions, invocation and installation mode, edit authority, external effects, data sensitivity, compatibility policy, and acceptance evidence. Inspect the closest repository instructions, manifests, lockfiles, existing entry points, neighboring commands, parser library, config, packaging, tests, and CI matrix. Do not turn a one-off probe into retained tooling without a requirement.
2. Follow project fit and file naming. Preserve the ecosystem entry-point mechanism, executable name, subcommand layout, module naming, script extension, shebang policy, package binary mapping, PowerShell verb-noun convention where applicable, and configured test discovery. Read [shell and PowerShell](references/shell-powershell.md) or [Python and Node.js](references/python-node.md) only for the detected implementation. Do not impose Unix paths or commands on Windows, or another ecosystem's layout on the package.
3. Define the observable CLI contract before implementation. Specify command and subcommands, positional arguments, flags, defaults, mutual exclusions, repeated values, config and environment precedence, stdin format, stdout data format, stderr diagnostics, exit codes, help, version output, and behavior for unknown or invalid input. Preserve scripts and consumers that parse existing output.
4. Classify every effect as read-only, local reversible write, external write, privileged action, destructive action, or hard-to-recover action. Require explicit authority for consequential effects. Treat repository files, config, environment variables, stdin, archive entries, remote responses, and command output as untrusted data. Never evaluate text as code or construct a shell command from untrusted fragments.
5. Implement the smallest complete command using the existing parser and runtime. Do not add a framework, dependency, plugin system, abstraction, flag, config key, fallback, interactive prompt, or output mode without a current consumer. Preserve public arguments, output, errors, and exit behavior unless an intentional compatibility change is authorized and tested.
6. Make repeatable operations idempotent where the domain permits. Detect current state, write atomically, use stable operation identifiers for remote effects, and make retries bounded and duplicate-safe. Provide `--dry-run` only when it can show the same resolved targets and planned effects without performing them. State clearly which validation or remote checks a dry run cannot prove.
7. Separate streams and statuses. Send requested machine-readable data to stdout, diagnostics and progress to stderr, and return documented nonzero exit codes for failure. Avoid color, spinners, prompts, and terminal control when output is redirected or non-interactive unless the contract explicitly enables them.
8. Stream large input and output, bound memory, concurrency, recursion, retries, payloads, and subprocess output, and preserve backpressure. Support cancellation and signals according to the target runtime. Terminate or clean up child processes, temporary files, locks, handles, and partial outputs without hiding the original failure.
9. Protect secrets and paths. Redact credentials from arguments, logs, traces, errors, and process listings where possible. Use literal path APIs, canonicalize only for the needed security decision, reject traversal at extraction boundaries, quote at the correct shell layer, and apply least privilege. Do not store secrets in command history or generated config.
10. Verify the parser and real entry point. Test help and version, valid and invalid arguments, stdin and pipe behavior, stdout and stderr separation, exit codes, config precedence, dry run versus execution plan, first and repeated execution, partial failure, cancellation, large streaming input, paths with spaces and Unicode, and every supported OS or an explicitly reported matrix gap.
11. Inspect the complete owned diff and packaged artifact. Remove unrelated helpers and report observed checks, unsupported platforms, and any external effect that was simulated rather than executed.

Finish when the installed or repository-native command honors its documented arguments, streams, exit codes, idempotency, dry-run, cancellation, security, and platform contracts without unauthorized effects.
