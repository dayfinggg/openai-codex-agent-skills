- [Node.js 26 node:test](https://nodejs.org/api/test.html) runs a file with `node --test tests/example.test.js`. Confirm named test bodies ran and assertions constrain the behavior. A file can exit successfully without meaningful assertions.
- [Vitest 5](https://vitest.dev/guide/cli.html) uses `vitest run tests/example.test.ts` for a terminating run. File filters use path inclusion. Confirm the actual selected file and test names rather than assuming an exact match.
- [Jest 30](https://jestjs.io/docs/cli) supports `jest --ci --runTestsByPath tests/example.test.js`. Exact path selection avoids accidental regex matching. Do not add `--passWithNoTests` to conceal a selection error.
- [pytest 9](https://docs.pytest.org/en/stable/how-to/usage.html) supports `python -m pytest tests/test_example.py::test_behavior`. Use the project's Python environment. [Exit code 5](https://docs.pytest.org/en/stable/reference/exit-codes.html) means no tests were collected, not success. Collection alone does not execute assertions.
- [PHPUnit 13.4](https://docs.phpunit.de/en/13.4/textui.html) accepts `vendor/bin/phpunit tests/ExampleTest.php`, with the project configuration loaded from the correct directory. Inspect tests, assertions, skipped, incomplete, and risky outcomes. [A test with no assertions or mock expectations is risky](https://docs.phpunit.de/en/13.4/risky-tests.html). Do not disable this signal.
- [Pest 5](https://pestphp.com/docs/filtering-tests) accepts `vendor/bin/pest tests/Unit/ExampleTest.php`. Use an inspected file or name filter. `--dirty` selects changed tests, which can omit unchanged consumer tests and is insufficient as the sole regression selection rule.
- [Go testing](https://pkg.go.dev/testing) and [go test](https://pkg.go.dev/cmd/go#hdr-Test_packages), documented for Go 1.27, support `go test -count=1 -v ./path/to/package`. `-count=1` disables successful test-result reuse. Inspect named tests and skips, not only the package's `ok`. Select the affected packages rather than expanding to `./...` automatically.
- [Cargo test](https://doc.rust-lang.org/cargo/commands/cargo-test.html), documented with stable Rust 1.99, supports `cargo test -p package_name behavior_name`. Filters can select zero tests successfully. Inspect every relevant test target's summary. `cargo test --no-run` only compiles. Preserve the project's feature and target configuration and include documentation tests when their contract changed.

For each meaningful run retain the following evidence in the session, not a new report file unless requested.

1. Record the exact executed command, working directory, source state, runtime or runner version where material, and the behavior selected.
2. Read useful stdout and stderr through termination and capture the producer's exit status. Do not let a pipeline, truncated output, or an earlier success banner conceal a later failure. Resume an existing background handle instead of starting duplicate runs.
3. Confirm that the intended tests were discovered, executed, and reached meaningful assertions. Inspect names and nonzero executed counts where available. Distinguish passes, failures, errors, skips, expected failures, risky tests, and filtered-out tests. Use more detailed reporter output only if selection or execution remains unclear.
4. Compare red and green evidence for the same behavior when working test-first. For a pre-existing failure, substantiate the baseline safely or report that attribution as unverified.
5. After the last edit, run the checks invalidated by that edit. Do not count results from an older source state as evidence for the final one.

The completion gate requires every requested behavior to have an appropriate executed check, affected existing contracts to have relevant regression evidence, and introduced failures to be fixed. When execution is blocked, run permitted independent alternatives and name their narrower scope. Report the original necessary check as unrun or failed with its actual reason. Do not substitute lint, a build, or a plausible-looking test file for a behavioral run. A smoke result establishes only the operation and environment it exercised.
