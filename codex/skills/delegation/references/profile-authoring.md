Create a persistent specialist only when the authorized task requires one. Prefer a task-scoped brief for one-off work. Do not install a roster, overwrite an existing agent, shadow built-in names, or change global defaults merely to dispatch a task.

1. Read the target host's current discovery rules and supported configuration schema. Do not copy another host's serialization, fields, tool names, or defaults. Use a unique name, precise routing description, bounded responsibility, necessary capabilities, evidence requirements, and completion conditions.

2. Keep reusable role guidance in the profile and task state in the brief. Reference only accessible tools and skills. Inherit model selection unless an explicit requirement needs a supported override. A profile cannot grant access beyond host policy or add cross-provider execution to an unsupported runtime.

3. Validate syntax, supported fields, discovery, and referenced resources. If behavioral testing is authorized, exercise a representative task and a case that should not select the profile. Check execution evidence and final artifacts, not the specialist's self-description. Compare a baseline before claiming gains in speed, cost, or quality.
