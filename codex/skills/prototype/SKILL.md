---
name: prototype
description: Build a disposable prototype to answer a design question or compare UI variants.
---

Identify the decision the prototype must settle.
For behavior or state models, read [LOGIC.md](references/LOGIC.md).
For visual alternatives, read [UI.md](references/UI.md).
Keep prototype files outside production paths unless the requested comparison needs the running app.
Use in-memory state or clearly isolated disposable storage.
Make the relevant state and differences visible, with only enough interaction to answer the question.
Report the observed result and its limits. Move validated behavior into production only when requested.
