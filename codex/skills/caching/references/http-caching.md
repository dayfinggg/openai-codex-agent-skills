1. Map browser, service worker, application, CDN and proxy caches on the affected path. Capture actual request/response headers and bodies, effective route configuration, cache status and origin requests. Determine the private/shared boundary, freshness owner and representation dependencies before attributing a stale response to a particular layer.

2. Define the URI/method key and header variants from actual response dependencies. Preserve meaningful query parameters, host, encoding, locale and identity boundaries. Vary selects request-header variants and does not authorize access. Check anonymous, authenticated and cross-tenant traffic separately. Never apply blanket public caching to secrets or personalized output.

3. Derive policy from [RFC 9111, sections 3 through 5](https://www.rfc-editor.org/rfc/rfc9111.html). no-store forbids storage, no-cache requires validation before reuse and private prohibits shared storage. Distinguish max-age, shared s-maxage, Age and must-revalidate. Vary star prevents ordinary reuse. Authorization requires shared-cache permission under section 3.5. Cookies alone do not prove HTTP storage is prohibited. Do not treat any directive as an authorization mechanism.

4. Keep validators representation-specific. Test If-None-Match with ETag and the applicable Last-Modified/If-Modified-Since path. A not-modified response must validate the selected representation, including its Vary dimensions. Preserve relevant metadata on 304 responses. After a write, test the old validator against the changed representation and verify the new body is eventually returned under the promised policy.

5. For Nginx, inspect the effective proxy_cache_key, eligible methods/statuses, bypass conditions, storage conditions, upstream freshness headers and inherited/overridden directives. proxy_cache_bypass suppresses cached reads. proxy_no_cache suppresses storage. Verify both where personalization requires it. Review proxy_ignore_headers before trusting upstream Cache-Control, Vary or Set-Cookie handling. Nginx normally avoids storing responses containing Set-Cookie. Do not remove that safeguard incidentally.

6. Bound origin load and stale behavior when changing proxy_cache_lock, background refresh, stale-on-error or expiry. Check lock timeout behavior and cache-space retention independently of freshness. Check the deployed build and edition before using purge features. Syntax, directive introduction versions and behavior belong in [Nginx proxy module documentation](https://nginx.org/en/docs/http/ngx_http_proxy_module.html), checked on 2026-11-05. Do not change unrelated cache zones or clear a shared cache for a benchmark.

7. Define which variants and cache layers must change after mutations, deployment or permission changes. HTTP invalidation on unsafe methods does not automatically purge every derived URL or CDN variant. Ensure a cached error or stale success cannot hide the requested change. Verify stale serving against the applicable protocol and implementation rules.

8. Verify a cold response, repeated hit, expiration, conditional validation and changed representation at the real affected cache boundary. Compare body, status and headers, then correlate cache status with origin work. A repeated 200 alone is not evidence of a cache hit. Test a user A response followed by user B and anonymous requests in both orders, along with relevant locale/encoding/query variants. Ensure a private response neither reads nor seeds the shared cache when that is the intended policy.

9. Validate an edited Nginx configuration using the deployed binary's configuration test and authorized configuration path before an authorized reload. A syntax test alone does not verify caching. If no proxy/CDN environment is available, report local response checks separately and leave the real cache-path check explicitly unverified.

10. Report the resulting storage/freshness behavior and the observed body/header checks. Identify any required targeted purge, key rollover or reload. Report effectiveness only after correctness, using comparable traffic for hit rate, origin work and latency.
