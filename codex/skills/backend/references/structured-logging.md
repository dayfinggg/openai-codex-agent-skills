1. Before editing, read the logger, processors, formatters, sinks, retention, buffering, and request or worker context. Identify the investigation the event must support and existing fields used by queries and alerts.
2. Give the event stable meaning and bounded fields for operation, outcome, error identity, and necessary context. Preserve existing field contracts and levels. Propagate actual request or trace context across changed HTTP and worker boundaries, clearing per-operation context before reuse. Do not fabricate trace IDs that cannot join the tracing system. Distinguish event time from collection time when delay matters, following the [OpenTelemetry Logs Data Model](https://opentelemetry.io/docs/specs/otel/logs/data-model/).
3. Use installed instrumentation's supported [semantic conventions](https://opentelemetry.io/docs/specs/semconv/registry/attributes/log/), including their stability status. Do not rename working application fields merely to adopt the latest convention. Bound serialized values and avoid duplicating the original body in attributes.
4. Exclude credentials, tokens, session secrets, authorization headers, connection strings, and sensitive bodies before they reach sinks. Inspect implicit object serialization, nested attributes, URL queries, exceptions, and debug paths as well as message text. Encode through the structured logger rather than concatenating untrusted strings. Verify carriage returns, newlines, and delimiters cannot forge events. Avoid logging the same exception at every layer without an operational reason. Apply [OWASP logging guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html).
5. Preserve configured failure, buffering, and backpressure behavior. Check whether sink failure blocks application work or loses critical evidence. Do not add an unbounded queue, install a logging platform, enable production debug output, or collect payloads outside the task's authorization.
6. Emit representative success and failure events through the real configured path. Verify parseable structure, field types, severity, redaction, correlation, delivery to the sink, and the consuming query. Use synthetic secret markers and confirm absence from final serialized output. Check concurrent requests or jobs for context leakage when propagation changes. Exercise sink failure and shutdown flushing when their behavior changes.
7. Report which diagnostic event now works and whether end-to-end delivery and the consuming query were checked. Name any unavailable sink or query instead of treating an in-memory logger test as delivery evidence.
