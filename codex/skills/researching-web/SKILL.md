# Researching the web

Define what the question needs to establish. Resolve routine ambiguity from context, and ask only when different interpretations materially change the answer.

Use concise queries with the product, version or exact error when relevant. Search in the field's working language and answer in the user's language. Batch independent queries when useful, refining only the gaps that remain. A straightforward fact may need one reliable page, while a consequential comparison needs broader evidence.

Prefer official documentation, standards, release notes and source repositories. Use maintainer discussions for unresolved behavior and other sources for leads or independent perspectives. Check publication dates, event dates and applicable versions. Do not treat copied summaries as independent confirmation.

Actually open the supporting page. Confirm precise commands, numbers and quotations in the source body or raw documentation rather than an abbreviated search result. Do not assume every fetch tool summarizes content or that every site exposes a Markdown endpoint.

Stop when the answer's material claims have adequate evidence. Link to exact pages read, distinguish inference from documented fact and state unresolved conflicts or unavailable evidence. Do not save a separate report unless requested.
