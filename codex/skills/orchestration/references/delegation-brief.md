# Define the worker contract

Delegate when authorized and when independent work or a fresh review will save time or catch blind spots. Keep dependent or small work in the current session. Assign separate files or an isolated checkout to each writer, and leave concurrent user work untouched.

Check the actual host tool for available models, effort, isolation, and completion signals. Keep the inherited model unless the user or runtime calls for another one. Use a fresh context when an independent reviewer must not see the author's reasoning. Use a fork only when the worker needs the conversation.

Give the goal, precise paths, work and write scope, relevant user constraints and rules, passing check, and stop conditions. State which external actions are out of scope. Give all workers the same shared capacity constraints and a way to take turns at heavy jobs. Ask for findings with file and line, check results, and any files or state changed. Pass long inputs as paths or narrow excerpts.

Use the runtime's completion mechanism. Continue independent work while workers run. Check their evidence and run the combined check before reporting the integrated result.
