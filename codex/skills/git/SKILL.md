---
name: git
description: Create commits or pull requests, resolve conflicts, or prepare a release.
---

Inspect the worktree, current branch, remote, and recent log before changing history.
Follow the repository's branch and commit conventions. Keep each commit to one logical, reviewable change.
Review the staged diff and keep credentials, private configuration, and unrelated generated files out.
Resolve conflicts from both sides' intended behavior, not by choosing one side wholesale.
Use [pull-requests.md](references/pull-requests.md) for pull request bodies.
For releases, follow the project's versioning policy. Under semantic versioning, use major for breaking changes, minor for compatible features, and patch for fixes.
Keep a requested changelog focused on user-visible changes and migration needs.
Follow the runtime's PR linking and monitoring rules.
