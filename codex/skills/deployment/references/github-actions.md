1. Read affected workflows, reusable/local actions, invoked scripts, runner configuration, required checks and current failing jobs. Identify supported events, branch/path filters, fork and Dependabot contexts, concurrency and cancellation behavior. Record the exact commit under test. Preserve required event coverage and user access while fixing the requested behavior.
2. Trace checked-out code, event strings, artifacts, caches and action outputs into privileged jobs. Never execute untrusted PR code with secrets or a write token through pull_request_target or workflow_run. Treat an upstream run's success as separate from its artifact's trust and identity. Preserve supported events by separating trust domains rather than deleting event handlers.
3. Declare the least GITHUB_TOKEN permissions each job needs. Specifying some permissions sets unspecified ones to none. All steps in a job share its token privilege, so separate untrusted build steps from publishing or deployment jobs. Check environment restrictions and runner isolation. For OIDC use id-token write only where needed and restrict the recipient's trust by repository, ref and environment. Do not broaden access or add approval stages incidentally.
4. Keep event text out of inline shell source. Pass untrusted values as data through quoted environment variables or action inputs, and validate values before using them as paths, refs or arguments. For agent workflows trace both event-to-prompt and model-output-to-script paths. Generated text must not become trusted shell code, a deployment target or permission to publish.
5. Respect the repository's workflow dependency lock mechanism. Otherwise pin changed external actions and reusable workflows to verified full commit SHAs from their originating repositories, and review their inputs and transitive execution. Verify supported versions for the actual runner. Never substitute an invented SHA or suppress dependency checks.
6. Keep caches and release artifacts separate. Key caches by relevant platform, toolchain and dependency inputs, and review restore-prefix and cross-branch trust. Do not store credentials in caches or allow an untrusted producer to supply a privileged executable. Tie release artifacts to the tested commit/run and digest, verify provenance or attestations when the pipeline uses them, and promote those bytes rather than a fresh untracked build.
7. Validate workflow YAML and action inputs using existing tooling, such as actionlint when available. Review event, permission, injection, cache and artifact boundaries manually even when a scanner passes. Do not install a new scanner or runtime interception layer merely because research recommends one.
8. Where authorized exercise the affected event and trust context, including rejection of untrusted input when that boundary changes. Inspect the actual commit's jobs, skipped paths, test counts, outputs and artifact identity. YAML parsing does not establish GitHub event semantics. Report any event-path check blocked by unavailable GitHub access. For waiting PR checks use the host's supported watcher and its handback rules instead of polling.

Use [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use) and [permissions and workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax). The targeted checks above also reflect [Granite](https://arxiv.org/abs/2512.11602), [agentic workflow injection](https://arxiv.org/abs/2605.07135) and [scanner coverage differences](https://arxiv.org/abs/2601.14455). These studies justify trust tracing and independent checks, not installing their proposed systems.
