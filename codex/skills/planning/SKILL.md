---
name: planning
description: Turn a complex request into ordered tasks with acceptance criteria, or write a requested plan.
---

Read the requirements and enough code to identify dependencies and risks.
Split the work into independently verifiable behavior changes, not separate database, backend, and frontend phases.
For each task, name its outcome, affected area, dependency, and focused check.
Resolve high-risk unknowns early. State assumptions that remain.
Use the session plan tool for ordinary implementation. Create plan files or tracker items only when requested or required by the repository.
Preserve unfinished plans for unrelated work.
When planning is part of an authorized implementation, continue after planning. Pause for plan approval only when requested or required by a real scope decision.
