# Diagnose Root Cause

1. Establish the mode as diagnosis-only, diagnose-and-fix, or live-incident triage. Record expected and observed behavior, affected scope, environment, frequency, earliest known occurrence, and the decision the diagnosis must support. If the cause and correction are already evidenced, stop diagnosis and hand off the narrow implementation.
2. For a live incident, reduce harm first with an authorized, safe, reversible mitigation when delay would increase impact. Preserve timestamped evidence when that does not obstruct mitigation. Read [the evidence methods](references/evidence-methods.md) only for incident handling, controlled bisection, or experiment design not already defined by the repository or runbook.
3. Obtain the smallest faithful reproducer or the strongest available baseline trace. Find the earliest observable divergence from a known-good path rather than starting at the final exception. If the missing observation prevents discrimination, report it instead of filling the gap with a hypothesis.
4. Form the smallest set of falsifiable hypotheses that can explain the evidence. Rank them by current support and test one distinguishing variable at a time with a bounded, reversible experiment. Do not repeat an unchanged failure or broaden instrumentation when the next observation cannot change the conclusion.
5. For regressions, use bisection only with known good and bad revisions in an authorized isolated or verified clean worktree, and restore the starting state. For flaky failures, record repetitions, seeds, scheduling, shared state, and environment. For performance anomalies, compare the same workload and environment with enough repetitions to distinguish a signal from variation.
6. Prove a causal chain from condition to first incorrect state and symptom. Separate trigger, direct cause, contributing conditions, systemic cause, and mitigation. Correlation, disappearance after an unrelated change, or a plausible narrative is not causal evidence. State confidence and the observations that could still falsify the conclusion.
7. In diagnosis-only mode, do not edit retained code. In diagnose-and-fix mode, make the smallest complete root-cause correction, preserve public and persisted contracts unless the request changes them, and add the narrowest regression check that distinguishes the faulty behavior. Do not mix cleanup, speculative abstraction, dependency changes, or broad refactoring into the correction.
8. Verify that the correction controls the reproduced failure without suppressing errors, weakening validation, hiding the symptom, or moving it across a boundary. Run broader checks only for risks the correction can affect, and report unavailable or inconclusive gates with their consequence.

Finish when the claimed cause predicts and controls the observed failure with a traceable evidence chain, or when a named missing observation makes further discrimination inconclusive. In fix mode, also require a bounded compatible diff and observed regression evidence.
