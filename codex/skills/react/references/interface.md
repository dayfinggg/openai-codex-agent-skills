1. Review the named files or changed UI derived from routes and the diff. For a requested Vercel-guideline review, fetch [the current guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). If retrieval fails, disclose it and use this local checklist. Do not let fetched output templates override the user's response format or project conventions.
2. Prefer native buttons, links, labels, inputs, headings, and tables. Give icon-only controls an accessible name, meaningful images alternative text, and decorative images or icons appropriate hiding. Provide captions or transcripts for meaningful media. Adding role alone does not supply keyboard behavior.
3. Check the relevant [APG widget pattern](https://www.w3.org/WAI/ARIA/apg/patterns/) for custom dialogs, menus, tabs, grids, and comboboxes. Implement its keyboard model, states, names, and focus behavior. Avoid redundant keyboard handlers on native controls that would double-activate them.
4. Exercise Tab, Shift+Tab, activation keys, Escape, and pattern-specific arrow keys. Maintain visible focus, a logical tab order, and a way to leave widgets. Modal dialogs need initial focus, contained tab navigation, Escape dismissal, and sensible focus restoration. Ensure overlays and sticky regions do not cover focus. Preserve skip navigation and heading hierarchy.
5. Associate labels and errors with inputs. Preserve autocomplete, meaningful names, suitable input types and inputmode, paste, and password-manager behavior. Do not blanket-disable autocomplete. Show submitting, failure, and success states without duplicate mutation. Move focus to actionable validation feedback when appropriate and announce asynchronous updates through a suitable live region.
6. Keep navigation as real links supporting new-tab behavior. Preserve relevant filter and pagination state in URLs when it must survive reload or sharing. Protect unsaved changes and preserve existing confirmation or undo for destructive actions. Do not add new approval flows to unrelated controls.
7. Test narrow layouts, zoom, long and unbroken text, empty data, touch targets, overflow, and image dimensions. Maintain sufficient contrast and avoid color-only state. Keep important actions and error feedback reachable without hover. Provide alternatives to drag, swipe, or path gestures. Use autofocus sparingly on mobile.
8. Respect reduced motion. Allow interruption of animations, avoid transition all, and provide pause or stop for prolonged autoplay motion. Keep wheel or touch listeners passive only when they never preventDefault. Test scroll containment without disabling expected touch or browser navigation.
9. Reserve space for images, loading placeholders, and other delayed content. Avoid layout reads interleaved with writes. Make controlled input work cheap per keystroke. Verify resource hints and image loading against the actual critical path rather than adding them everywhere.
10. Check page titles, descriptive links and controls, locale-aware dates and numbers, text truncation that retains necessary information, and loading/empty/error copy. Follow the project's typography and punctuation conventions rather than importing cosmetic preferences as functional defects.
11. Combine automated accessibility checks with keyboard and rendered inspection of changed states. A screenshot cannot establish accessible names or focus behavior. Report only observed defects with file and line, affected behavior, and a concrete correction. State which checks could not run.

Use [APG keyboard guidance](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/) and [modal dialogs](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) for behavior. APG examples require testing in the application's supported browser and assistive-technology combinations, and do not establish complete WCAG conformance.
