1. Draw the actual data dependency chain. Start independent reads together and await dependent reads only after their inputs exist. Keep side effects and authorization in their required order. Check cheap pure guards before unused remote work. Attach rejection handling to early-started work even when a branch exits. Avoid adding a parallelism library for ordinary promise composition.
2. Use the existing framework loader or client cache to deduplicate requests. Share genuinely global subscriptions when repeated listeners cause duplicate work. Specify loading, empty, failure, and retry behavior. Prevent an outdated response from replacing newer data after navigation or rapid input. Clean up subscriptions, timers, and owned requests on unmount.
3. Place Suspense boundaries around independently loadable content with a useful size-stable fallback. Do not block an entire layout on a child read when independent content can stream. Preserve required metadata, SEO content, and layout correctness. Suspense does not detect arbitrary effect-based fetching.
4. Identify App Router versus Pages Router and Node versus Edge constraints. Keep secrets and server-only modules on the server. Place use client at the smallest interactive boundary. Server-rendered components may be passed through children slots without importing server code into the client graph. Only pass React-serializable props and fields the client needs.
5. Authenticate and authorize each directly callable Server Action or route at the mutation boundary. Validate external inputs there. Layout visibility or middleware alone is insufficient. Preserve the established access policy rather than adding a new one during optimization.
6. Distinguish request memoization, persistent data caching, full route caching, and client router caching. Read the installed Next.js release and cacheComponents setting before changing directives or revalidation APIs. React.cache deduplicates within a React server render pass, not across requests or ordinary Server Action and Route Handler calls. Stable primitive arguments improve memoization where identity determines reuse.
7. Keep mutable request and user state out of module scope. Hoist only immutable reusable assets or intentionally shared clients and correctly keyed bounded caches. Check tenant isolation, invalidation after mutation, repeated requests, process reuse, cold starts, memory limits, and rejected initialization before adopting shared caching.
8. Keep server output and the first client render consistent. Do not read window or localStorage during SSR. Use the existing supported theme/bootstrap mechanism when needed and preserve CSP and escaping. Reserve suppressHydrationWarning for unavoidable isolated differences, never incorrect markup, unstable keys, or broken data flow.
9. For optional post-response work, use after only on a supporting Next.js version and platform, await its callback work, and respect the route duration limit. It can execute after redirects or failures. Do not move success-critical writes, durable notification delivery, or required audit records into an unguaranteed detached path.
10. Inspect the production bundle or trace before changing imports. Use supported typed package subpaths, not undocumented dist paths. Keep dynamic import targets statically analyzable. A typeof window check does not by itself remove a module from a bundle.
11. Lazy-load expensive optional UI without delaying critical content. Use next/dynamic only within the version's permitted server/client boundary. Consider hover and keyboard-focus preloading only for likely interactions. Keep analytics, scripts, and error reporting consistent with product requirements rather than deferring all observability indiscriminately.
12. Use the framework's script strategy or defer for ordered DOM-dependent scripts and async only for independent scripts. Limit resource hints to resources the page actually needs. Preserve image dimensions, avoid lazy-loading the critical image, and verify the installed version's image priority API. Reduce SVG precision only with visual comparison.

Consult the version-matched equivalents of [server/client boundaries](https://nextjs.org/docs/app/getting-started/server-and-client-components), [caching](https://nextjs.org/docs/app/getting-started/caching), [authentication](https://nextjs.org/docs/app/guides/authentication), and [after](https://nextjs.org/docs/app/api-reference/functions/after) for the changed path. [Vercel React rules](https://github.com/vercel-labs/agent-skills/tree/main/skills/react-best-practices) supply optimization candidates, not permission to install dependencies or promises of fixed speedups.
