1. Keep state at the nearest common owner that needs it. Use props first. Introduce a provider when distant or independently composed consumers genuinely need one state owner. Do not mirror child state upward through an effect or read mutable refs as a substitute for the UI's state contract.
2. When interacting boolean modes permit impossible combinations, use an explicit variant or composed subcomponents. Keep ordinary boolean properties such as disabled. Prefer children for static slots and render props when the parent must supply data. Preserve existing public props unless an API change is requested.
3. For compound components, put the provider above every consumer, including controls visually outside the frame. Expose the state and operations consumers need without prescribing state/actions/meta fields for every component. Isolate storage implementation only where a real alternate owner or testing boundary requires it.
4. In React 19, ref can be a prop, but retain forwardRef for supported older consumers. useContext remains supported. Do not replace it mechanically with use or introduce React 19 APIs into React 18 packages. Check both runtime React and its type package.
5. Split unrelated effect synchronization by dependency set. Use the actual reactive dependencies rather than suppressing hook lint. Narrow subscriptions to the slice rendered. Avoid subscribing during render to a value only needed by an event callback when the store supports a safe current-value read.
6. On versions supporting useEffectEvent, use it only for genuinely non-reactive logic invoked by an effect or its callbacks. Keep reactive dependencies. Do not include Effect Events in dependency arrays, pass them to other components, or treat them as stable-identity callbacks. On older versions use the existing subscription pattern and a correctly synchronized ref when necessary.
7. Treat mount, cleanup, and remount as valid lifecycle paths. Make external initialization idempotent and place application-wide initialization at the existing entry boundary. A process-wide module guard must not suppress user-specific work on later SSR requests. Lazy state initializers must remain pure and SSR-safe.
8. Measure the expensive path before adding memo, useMemo, useCallback, or static JSX hoisting. With React Compiler enabled, inspect remaining work before layering manual memoization. Keep memo dependencies complete and default object identities stable where equality actually matters. Do not memoize cheap scalar expressions.
9. Use transitions for non-urgent rendering, and deferred values for slow derived views while keeping input updates immediate. They do not cancel network requests or replace every loading state. Isolate the expensive subtree so deferred rendering can skip urgent renders. Verify stale-result indication and completion ordering.
10. For long lists, choose virtualization or content-visibility from measured layout and memory cost, not a fixed row threshold. Preserve focus, findability, scroll position, and accessible content. Consider Activity only on supported React versions when preserving hidden state is required, and check effect cleanup when hidden.
11. Batch layout reads before writes and avoid DOM measurements during render. For animation, prefer compositor-friendly properties and verify SVG wrapper or group transforms in the target browser rather than assuming a wrapper guarantees acceleration.
12. Optimize repeated lookup or transformation work only in an observed hot path. Preserve equality semantics, ordering, immutability, and stateful RegExp.lastIndex behavior. Bound caches and define invalidation before caching function or storage results. Version persisted schemas and store only needed fields. Browser storage may throw, may change in another tab, and must not become an accidental store for secrets or unnecessary personal data.
13. Schedule only non-urgent background work in idle callbacks. Check target-browser support, chunk work within the idle budget, cancel owned callbacks on disposal, and retain a fallback or timeout for work that must eventually run. Do not delay user-awaited rendering or time-sensitive actions until idle. The [W3C scheduling draft](https://www.w3.org/TR/requestidlecallback/) permits indefinite postponement without a timeout.

Resolve disputed API advice against [useContext](https://react.dev/reference/react/useContext), [Effect Events](https://react.dev/reference/react/useEffectEvent), and [unnecessary effects](https://react.dev/learn/you-might-not-need-an-effect). Use [Vercel composition patterns](https://github.com/vercel-labs/agent-skills/tree/main/skills/composition-patterns) as conditional design options rather than mandatory architecture.
