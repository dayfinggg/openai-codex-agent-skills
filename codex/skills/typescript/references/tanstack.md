1. Identify each changed @tanstack package and its exact locked or installed version. Select Query, Router or Start, Form, and Table independently. Their major versions are not interchangeable.
2. Locate relevant SKILL.md files shipped with the installed package and its metadata. If the project already uses TanStack Intent, use its existing list and load commands after checking their installed CLI semantics. Otherwise read package-owned files directly. Do not run a floating npx command, install Intent solely for discovery, install hooks, inject gates, or edit managed AGENTS.md blocks.
3. If package skills are absent, use official documentation for the locked or explicitly selected version. Missing packaged instructions do not block a documentation-based fix. Do not substitute latest semantics or upgrade the package to follow a skill.
4. For Query, inspect complete query keys including tenant and filters, staleTime versus inactive retention, retry and refetch triggers, invalidation after mutations, cancellation signals, and optimistic rollback under overlapping updates. Preserve the existing data library rather than adding SWR for deduplication. Check hydration and separate request-scoped clients during SSR.
5. For Router or Start, inspect validated path and search parameters, loader dependencies and cache keys, preload versus navigation, abort propagation, authentication boundaries, redirects, and SSR state transfer. Do not assume a navigation change always aborts a shared preload invocation.
6. For Form, inspect default values, subscriptions, validation timing, synchronous versus asynchronous validation, stale validation results, submit failures, and server validation. Exercise rapid edits and failed submit when those paths change. Client validation does not authorize a server mutation.
7. For Table, keep controlled state and its change callback together. Do not set the same state in both initialState and state. Distinguish client row models from manual server pagination, filtering, and sorting. Server-paginated rows must not be paginated again. Verify row identity, totals, empty results, and page resets after filters or deletions.
8. Verify types, the affected build, and the real data path. For changed SSR or mutations, include failure, navigation, and repeat-request behavior. Do not claim persistence based only on an optimistic UI update.

Use [Intent](https://tanstack.com/intent/latest/docs/overview) to verify discovery semantics. Read only the relevant installed-version equivalent of [Query defaults](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults), [Router loaders](https://tanstack.com/router/latest/docs/guide/data-loading), [Form validation](https://tanstack.com/form/latest/docs/framework/react/guides/validation), or [Table v8 pagination](https://tanstack.com/table/v8/docs/guide/pagination). Live latest URLs are discovery entry points, not a version match.
