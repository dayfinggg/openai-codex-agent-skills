# Reflect

Turn observed behavior into the smallest justified improvement.

## Gather evidence

Review the objective, decisions, corrections, failures, verification results, and user feedback. Identify where the process saved effort, created rework, missed evidence, or required repeated instruction.

## Classify the lesson

Distinguish a one-off circumstance, project convention, tool limitation, skill-routing problem, missing procedure, and enforceable mechanical rule. Put project-specific facts in project guidance. Prefer a script, lint, or check for deterministic constraints. Reserve skill changes for reusable judgment or workflow.

## Test the proposal

State the observed failure, intended behavior, owning skill or project rule, and a realistic verification scenario. Make a narrow proposal, or apply and verify it when edits are authorized. Do not broaden a skill for speculative edge cases.

## Boundaries

Do not edit skills or project rules unless the request authorizes changes. Preserve unrelated existing instructions. Report when evidence is too weak to justify a change.

## Output

Report observations, reusable lessons, their destination, proposed or completed changes, and verification evidence or limits. Distinguish an untested proposal from an observed improvement.
