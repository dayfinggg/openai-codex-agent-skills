Default execution flow

  1. InspectRead the nearest rules and current project state.
  2. DecideChoose one focused workflow and a verifiable outcome.
  3. ChangePreserve user work and keep the implementation bounded.
  4. VerifyRun the narrowest useful checks, then broaden by risk.
  5. ReportState the result, evidence, caveats, and next action.

Operating method

Less ceremony. More proof.

The catalog does not add a universal checklist to every task. Each skill activates only for the work it owns and keeps completion tied to observable evidence.

01

Evidence before edits

Repository rules, nearby patterns, versions, and runtime behavior come before assumptions. Current external facts are checked against primary sources.

02

Smallest complete change

The agent solves the requested problem without speculative abstractions, unrelated cleanup, fake implementations, or hidden scope expansion.

03

Risk-based verification

Checks start close to the changed behavior and expand only when the risk justifies it. A polished diff is not treated as proof.

04

Human reports

Final answers read as connected prose: the outcome comes first, each paragraph develops one topic, and evidence follows in a logical order. Lists remain an exception for real procedures or independently checkable items, not a default report format.

Codex design-ui-ux

Designed for a task, not generated for a screenshot.

The UI/UX skill scales from a single setting to role-based workspaces. It preserves platform conventions, real content, accessibility, and public-web discoverability without turning every surface into cards.

Clear hierarchy. Real states. Fewer, stronger choices.

Complexity changes the process

Simple views need a clear task and feedback. Complex products also need information architecture, roles, permissions, data responsibilities, and recovery.

Containers must carry meaning

Cards are reserved for self-contained objects or interaction boundaries. Tables, lists, canvases, timelines, and plain sections stay available.

SEO has a boundary

Search guidance applies only to public pages intended for discovery. Private product screens stay optimized for orientation and action.

Generated UI remains a draft

Structured design context, real content, targeted feedback, rendered verification, and human judgment decide release readiness.

Installation

Start with the files you need.

Clone the repository, copy the matching catalog, and restart the application. Keep machine-specific configuration separate.

OpenAI Codex

Install the operating policy, specialist agents, and the 13-skill Codex catalog.

git clone https://github.com/dayfinggg/claude-code-codex-skills.git
cd claude-code-codex-skills
cp -R codex/agents codex/skills "$HOME/.codex/"
cp codex/model-instructions.md "$HOME/.codex/"

Claude Code

Install Claude's working rules, output style, specialist agents, and 18 focused skills.

git clone https://github.com/dayfinggg/claude-code-codex-skills.git
cd claude-code-codex-skills
cp -R claude/skills claude/agents \
  claude/output-styles "$HOME/.claude/"
cp claude/CLAUDE.md "$HOME/.claude/"

The repository also includes update scripts for macOS, Linux, and Windows. They preserve unrelated local configuration and back up conflicts before replacement. Review the README before using them on a customized installation.
